# Технический аудит сайта «Сладкий Град»

**Дата:** 19.08.2026
**Объект:** `samcoder18/Grad` — SPA-лендинг (React 19 + Vite 6 + Tailwind v4), деплой на GitHub Pages (`base: /Grad/`)
**Методы:** статический анализ всего `src/` (25 файлов), сборка `vite build`, прогон production-бандла в браузере (Playwright, десктоп 1440×900 / мобильный 375×812), анализ сети, консоли, accessibility-дерева, репозитория и CI.
**Скриншоты:** `.playwright-mcp/audit/`

---

## 1. Резюме

Сайт визуально сильный и технически аккуратный для лендинга: чистая сборка, ноль ошибок в консоли, ноль 404, корректная работа с `base`-путями, внятные alt-тексты, хорошая поддержка `prefers-reduced-motion`. Но есть несколько проблем, которые для production-системы критичны: публичный «виртуальный офис» с финансовыми данными компании без какой-либо пометки «демо», 6.4 МБ трафика на первом экране, системные провалы keyboard-доступности и неработающий кириллический дисплейный шрифт.

| Область | Оценка | Ключевая проблема |
|---|---|---|
| Архитектура / код | 7/10 | GSAP + Motion дублируют друг друга в одном бандле |
| Производительность | 4/10 | 6.4 МБ первой загрузки, 4.9 МБ eager-картинок |
| Доступность (a11y) | 4/10 | Карта и карусель недоступны с клавиатуры, контраст < AA |
| SEO | 5/10 | Нет JSON-LD, canonical, robots.txt, sitemap, два h1 |
| Безопасность / приватность | 3/10 | Публичный «офис» с финансами, контрактами и ФИО |
| UX / дизайн | 8/10 | Сильная подача; перегруз первого экрана на мобильном |
| Надёжность | 5/10 | Нет ErrorBoundary — падение чанка = белый экран |
| Деплой / репозиторий | 6/10 | CI только собирает; 14 МБ мусора в git |

### Приоритеты

- **P0:** пометить/скрыть «Виртуальный офис» (утечка финансовых и кадровых данных); форма «Партнёрская сеть» обещает ответ, но никуда не отправляет данные.
- **P1:** производительность (ленивая загрузка изображений, респонсив-варианты, вынос GSAP); ErrorBoundary для lazy-чанка; контраст текста на градиентах вкусов.
- **P2:** keyboard-доступность карты/аккордеона/меню; кириллический fallback вместо Anton; структурированные данные и meta-файлы.

## 2. Безопасность и приватность

### 2.1. Публичный «Виртуальный офис» — главный риск (P0)

Внутренний CRM-интерфейс доступен любому посетителю: кнопка «Офис» в десктопной навигации (`src/components/Nav.jsx:74-81`), «Виртуальный офис» в мобильном меню (`Nav.jsx:126-137`). Никакой авторизации, переключение — `useState("landing" | "office")` в `App.jsx:27`. Чанк `OfficeShell-*.js` (110.8 КБ) публично скачиваем независимо от UI.

Проверено в браузере: офис открывается и показывает:

- **Финансовые KPI:** план 12,4 млн ₽, оборот 14,1 млн ₽, дебиторка 2,3 млн ₽ (`src/data/office.js:37-39, 69-71`).
- **Сделки** с суммами до 2 100 000 ₽ (`office.js:155`).
- **Договоры:** № 114/08 на 6 200 000 ₽ (`office.js:197-202`), хеш ЭЦП `5D3F A912 C0E8 44B7` (`office.js:228`, выводится как «Подпись:» в `Contracts.jsx:114`), «сертификат действителен до 12.03.2027» (`office.js:223`).
- **Руководство с правдоподобными ФИО:** «Марина Соколова, генеральный директор» и др. (`office.js:7-27`).

Данные моковые (комментарий «Mock data» в `office.js:1`, шуточные фамилии сотрудников — Сластёнов, Карамель, Копейкин), но **в UI это нигде не обозначено** — только виджет видеозвонка признаётся, что он демо (`Clients.jsx:90`). Посетитель, партнёр или конкурент с высокой вероятностью примет это за реальную финансовую отчётность, реальные договоры и реальных топ-менеджеров компании. Это одновременно репутационный, юридический (фиктивные договоры и ЭЦП) и конкурентный риск.

**Рекомендация:** либо убрать офис из публичной навигации и защитить маршрут, либо добавить явный водяной знак/баннер «Демонстрационные данные» на каждый модуль и заменить правдоподобные ФИО руководства.

### 2.2. Форма-обманка (P0)

`PartnerNetwork.jsx:116-146` собирает «компания / контакт / телефон» и показывает «Заявка принята… коммерческий директор свяжется» (`PartnerNetwork.jsx:94-103`). Данные никуда не отправляются. Пользователь вводит персональные данные, получает ложное подтверждение — это и UX-обман, и проблема по 152-ФЗ (сбор ПДн без цели и согласия).

### 2.3. Что в порядке

- Нет `dangerouslySetInnerHTML`, внешних скриптов, CDN, секретов в коде (grep-проверено).
- Единственная внешняя ссылка `wa.me` — с `target="_blank" rel="noreferrer"` (`Footer.jsx:29-31`). Корректно.
- CSP отсутствует (GitHub Pages не даёт выставить заголовки; приемлемо, но на будущее — meta-CSP снизил бы риски при подключении сторонних сервисов).

## 3. Производительность

Замеры production-бандла (`vite preview`, локально; абсолютные тайминги нерепрезентативны, веса — точны).

### 3.1. Вес первой загрузки

| Ресурс | Объём | Комментарий |
|---|---|---|
| **Итого transferred** | **~6.4 МБ** | критично много для лендинга |
| Изображения | 17 файлов, ~4.9 МБ | все загружаются eager |
| JS main chunk | 532.6 КБ raw / 176.2 КБ gzip | предупреждение Vite >500 КБ |
| JS OfficeShell chunk | 110.8 КБ / 29.3 КБ gzip | lazy, ок |
| CSS | 63.6 КБ / 15.3 КБ gzip | ок |
| Шрифты | ~1.1 МБ суммарно | включая 118 КБ unbounded latin-ext |

### 3.2. Проблемы

1. **Все 7 бутылок вкусов грузятся сразу** — ручной preload через `new Image()` на маунте (`FlavorAccordion.jsx:111-115`) и отсутствие `loading="lazy"` (`:281-291`). 14 изображений по 390–460 КБ (`cola.webp` 460K, `mojito.webp` 459K, `orange.webp` 452K…) — это ~80% веса страницы. Респонсивных вариантов (кроме hero) нет: мобильный клиент скачивает те же 460 КБ на бутылку.
2. **Мобильный hero тяжелее десктопного:** `hero-bg-mobile.webp` 230K против `hero-bg.webp` 156K — инвертировано относительно здравого смысла.
3. **Две анимационные библиотеки в одном бандле:** `motion@12` используется почти везде, а `gsap@3.12.7 + ScrollTrigger` — только в двух секциях (`Manifesto.jsx:2-3`, `Gudis.jsx:2-3`), которые импортированы статически. GSAP (~70 КБ gzip) физически не может быть вырезан. Нет `manualChunks` (`vite.config.js` — 9 строк).
4. **Anton для кириллицы:** `anton-latin` скачивается (18.6 КБ), но кириллических глифов в нём нет — браузер грузит шрифт впустую, а текст рендерится fallback'ом (см. §6.3).
5. Локальный FCP 464 мс; реальный LCP на мобильной сети при 6.4 МБ будет далеко за таргетом 2.5 с.

### 3.3. Рекомендации

- `loading="lazy"` + `decoding="async"` на все изображения ниже первого экрана; preload только активного вкуса карусели, остальные — по требованию.
- Сгенерировать `-mobile`/`-sm` варианты бутылок (srcset/sizes), пережать webp (quality ~75, ресайз до реальных размеров рендера).
- Переписать Manifesto/Gudis на Motion (он уже в бандле) и удалить GSAP, либо lazy-импортировать секции с GSAP.
- Добавить `build.rollupOptions.output.manualChunks` (react / vendor анимаций).

## 4. Доступность (WCAG)

### 4.1. Критичные провалы (клавиатура)

- **Карта полностью недоступна с клавиатуры:** `expand-map.jsx:43-58` — `motion.div` с `onClick`, без `role="button"`, `tabIndex`, обработчика клавиш, `aria-expanded`. WCAG 2.1.1 — провал уровня A.
- **Боковые бутылки карусели** — `role="button"` + `onClick`, но без `tabIndex` и keyboard-обработчика (`FlavorAccordion.jsx:274-279`) — фокусируемых псевдокнопок нет.
- **Мобильное меню:** нет `aria-expanded`/`aria-controls` (`Nav.jsx:93-100`), нет закрытия по Escape, нет управления фокусом.
- **Глобальный перехват клавиш:** ArrowLeft/ArrowRight на `window`, когда секция вкусов ≥50% в зоне видимости (`FlavorAccordion.jsx:149-169`) — отнимает стрелки у скринридера и скролла.
- **Автоплей карусели:** пауза по hover/touch/reduced-motion есть, но у keyboard-only пользователя нет контроля паузы (WCAG 2.2.2). `aria-live="polite"` (`:315`) озвучивает смену вкуса каждые 4 секунды — шумно.
- **Focus-стили отсутствуют:** `focus:`/`focus-visible:` встречается только в форме офиса (`PartnerNetwork.jsx:23`). На лендинге навигация по Tab слепая.

### 4.2. Контраст (расчётный)

| Пара | Контраст | Норма AA | Вердикт |
|---|---|---|---|
| Белый на `--color-pear` #d99a06 | 2.4:1 | 4.5:1 | провал |
| Белый на `--color-orange` #f26d1b | 3.0:1 | 4.5:1 | провал (мелкий текст) |
| Белый на `--color-tarragon` #2fa84f | 3.0:1 | 4.5:1 | провал |
| `--color-gudis` #1287d4 на тёмном градиенте | 3.6:1 | 3:1 (крупный) | проходит только как large text |
| Белый на brand #d91e36 | 4.6:1 | 4.5:1 | на грани |

Мелкий описательный текст в карусели вкусов (`FlavorAccordion.jsx:319-325`) на ярких градиентах нечитаем по нормам. На мобильном hero заголовок лежит прямо на этикетках бутылок без подложки-скрима — местами белое по светло-зелёному (подтверждено скриншотом `audit-mobile-hero.png`).

### 4.3. Семантика

- **Два `<main>`** при открытом офисе: `App.jsx:36` оборачивает `OfficeShell.jsx:120` — два main-лендмарка (подтверждено в accessibility-дереве).
- Секция `#about` (`Manifesto.jsx:61-84`) не имеет заголовка — якорь «О компании» ведёт в секцию без heading.
- `expand-map.jsx:328` — `<motion.h3>` для адреса (оформительский заголовок).
- Имена заголовков склеены из-за inline-картинок: «Литровые хитыDolceкончаются первыми», «Gudis:вода Центрального Кавказа» (видно в accessibility-дереве) — для скринридеров и парсеров текст читается слитно.
- Адрес — обычный `<p>` вместо `<address>` (`LocationSection.jsx:29-35`).

### 4.4. Что хорошо

- Осмысленные alt у всех продуктовых изображений; декоративные — `alt=""` + `aria-hidden`.
- Побуквенный hero-заголовок: буквы `aria-hidden`, на h1 — `aria-label` (`Hero.jsx:125`).
- Reduced-motion: `useReducedMotion()` почти везде, matchMedia-гварды перед GSAP (`Manifesto.jsx:20`, `Gudis.jsx:50`), CSS kill-switch (`index.css:109-119`), обработка `prefers-reduced-transparency` для стекла (`index.css:86-92`). Минус: проверки matchMedia только на маунте — смена OS-настройки в живой сессии не подхватывается.
- `lang="ru"` (`index.html:2`).

## 5. SEO

- **Два `<h1>` в выдаваемом HTML** — мобильная (`Hero.jsx:191`) и десктопная (`Hero.jsx:263`) ветки обе в DOM, одна лишь скрыта CSS. Подтверждено в рантайме (`document.querySelectorAll('h1').length === 2`).
- **Нет структурированных данных** — ни Organization/Product/LocalBusiness JSON-LD, хотя точный адрес и координаты захардкожены (`LocationSection.jsx:33-34`, `expand-map.jsx:11-12`). Для производителя с физическим адресом — прямая потеря rich-результатов.
- Неполные OG: есть title/description/image (`index.html:11-16`), нет `og:type`, `og:url`, `og:locale`, canonical, Twitter Card.
- Нет `robots.txt`, `sitemap.xml` (проверено в `public/` и `dist/`).
- `icon-192.png`/`icon-512.png` лежат в `public/`, но не подключены нигде — ни в HTML, ни в (отсутствующем) `manifest.webmanifest`.
- SPA на GitHub Pages без `404.html`-фолбэка — сейчас маршрутов нет, но при их появлении прямые ссылки сломаются.
- Плюсы: title/description уникальны и содержательны, все якоря навигации резолвятся в реальные id, `tel:`/`mailto:`/`wa.me` консистентны с отображаемыми контактами (`data/flavors.js:87-88`, `Cta.jsx:66,87`, `Footer.jsx:29,38,79`), og:image — абсолютный и существующий.

## 6. UX / дизайн (по чек-листу taste-скиллов)

Вердикт в целом: уровень заметно выше типового «AI-лендинга». Нет фиолетовых градиентов, нет трёх одинаковых карточек, нет дешёвых мета-лейблов («SECTION 01»), нет липовых скриншотов из div'ов, ритм секций разнообразный (hero → marquee → аккордеон → bento → манифест → тёмная секция → CTA → карта).

### 6.1. Проблемы

1. **Anton на кириллице не работает** (главный визуальный баг): `fontFamily: "'Anton'"` применён к русскому тексту — гигантские названия вкусов (`FlavorAccordion.jsx:237,257`) и ссылка «Заказать» (`:355`). У `@fontsource/anton` нет кириллического сабсета (проверено в собранном `dist/assets/` — только latin/latin-ext/vietnamese). Текст молча рендерится системным sans — дизайн-смысл элемента теряется, а на скриншоте `audit-flavors.png` видно, что «ВИНОГРАД» набран не тем шрифтом. Латинские бренды (Dolce Cola) при этом рендерятся правильно — рассинхрон заметен.
2. **Мобильный hero перегружен:** заголовок и подзаголовок лежат прямо на этикетках бутылок («МОХИТО», «ВИНОГРАД» пробиваются сквозь текст), скрима нет. CTA видны без скролла — это плюс.
3. **Инверсия темы:** светлая страница с тёмной Gudis-секцией посередине. По правилу theme-lock — нарушение; здесь выглядит осознанным бренд-блоком, но переход стоит сгладить.
4. **Дублирование CTA-интента:** «Оформить заказ» (nav, hero, bento, CTA, Gudis) + «Заказать» (карусель) — один интент, два лейбла. Мелочь, но по дисциплине — один ярлык на интент.
5. Копирайт: «Сладкий Град это брендированное производство…» — пропущено тире (`Manifesto.jsx:8`); подпись «оптовая цена за бутылку от» под значением «50 ₽» читается коряво (`Manifesto.jsx:13`). Тире в русском тексте («ингредиент — вода») типографически корректно — правило скилла про em-dash здесь неприменимо.
6. Один marquee, eyebrow один («Где мы находимся») — в рамках лимитов. Bento `HitsBento`: 4 продукта + CTA-плитка, ячеек ровно столько, сколько контента — ок.

### 6.2. Сильные стороны

- Hero влезает в viewport, заголовок 2 строки, CTA без скролла, реальные продуктовые фото.
- Анимации мотивированы (reveal, scrub-манифест, карусель), reduced-motion обработан.
- Единый акцент (brand-красный #d91e36) по всей странице; единая система радиусов.
- Нет горизонтального скролла на 1440 и 375 (проверено в рантайме).

## 7. Надёжность

- **Нет ErrorBoundary вообще.** Lazy-чанк офиса (`App.jsx:14, 65-67`) в `<Suspense>` без границы ошибок: типичный сценарий GitHub Pages — пользователь с открытой вкладкой ловит редеплой, хеши файлов меняются, чанк 404 → всё приложение падает в белый экран.
- **Позиционная деструктуризация:** `const [cola, mojito, orange, lime] = hits` (`HitsBento.jsx:66`) — молча ломается при перестановке данных в `data/flavors.js:55-84`. Аналогично незащищённые обращения в `OfficeShell.jsx:13-14`, `Department.jsx:68-69`, `Deals.jsx:7`.
- **Утечки эффектов (минорные):** `document.fonts?.ready.then(refresh)` (`Gudis.jsx:92`) может вызвать `ScrollTrigger.refresh()` после размонтирования; таймаут `animatingRef` (`FlavorAccordion.jsx:143-145`) не очищается.
- **Нет onError-фолбэков у изображений** — битый webp = иконка сломанной картинки (размеры hero зарезервированы — CLS защищён, `Hero.jsx:243-244`).
- Что хорошо: cleanup'ы GSAP/matchMedia/IntersectionObserver/resize/visibilitychange почти везде (`Manifesto.jsx:57`, `Gudis.jsx:93-96`, `Hero.jsx:97-102`, `FlavorAccordion.jsx:116-118,133-137,164-167`); StrictMode включён (`main.jsx:10-12`), двойной маунт безопасен.

## 8. Архитектура и качество кода

- Плоская композиция секций в `App.jsx:46-55`, без роутера; единственный lazy-баундари — офис. Для лендинга приемлемо.
- **Дублирование:** easing `[0.16, 1, 0.3, 1]` объявлен 4+ раз (`App.jsx:16`, `Hero.jsx:13`, `HitsBento.jsx:6`, `OfficeShell.jsx:8`); массив nav-ссылок продублирован в `Nav.jsx:13-19` и `Footer.jsx:5-11`.
- **Два механизма брейкпоинтов:** `useMediaQuery("(min-width: 1024px)")` (`Hero.jsx:93-104,143`) против `window.innerWidth < 640` + resize (`FlavorAccordion.jsx:107-118`) — магические числа дублируют брейкпоинты Tailwind.
- Смешанный стиль: FlavorAccordion ~50% inline-стилей, HitsBento — чистый Tailwind. Один eslint-disable (`FlavorAccordion.jsx:168`).
- Все ассеты идут через helper `src/lib/asset.js:3` с `import.meta.env.BASE_URL` — **это правильно**, все 22 файла на месте. Абсолютные пути в `index.html:17-23` Vite корректно переписывает под `/Grad/` при сборке (проверено в `dist/index.html`), но в `vite dev` preload hero молча 404'ит.
- Нет тестов, линтера, форматтера, typecheck — `package.json` содержит только `dev/build/preview`.

## 9. Репозиторий и деплой
